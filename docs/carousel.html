Retrieval-augmented generation

What it takes to
make RAG work on
regulation.

Four AI-governance documents, a system that answers only from them, and an evaluation built to locate where it fails.

NIDHI PARKER01
The mechanism

The model does not
answer from what it
learned in training.

It answers from passages fetched out of a fixed corpus at query time, and is constrained to those passages.

Which relocates the problem. System quality is no longer model quality — it is whether retrieval put the right evidence in front of it, and that is the part this measures.

WHAT RAG IS02
Why this corpus

On regulation, an
unciteable answer
is not an answer.

The AI Act was amended in July 2026. A model answering from training text cannot tell you which version it learned, or point you at the clause.

Every claim here carries a citation to the article, annex or page it came from, so the reader can verify it rather than trust it.

WHY IT MATTERS03
The evidence library

Four sources that
overlap in subject and
differ in force.

EU AI ActBINDING LAW
The regulation. Defines high-risk classification and the obligations that follow from it. Consolidated text, including the 2026 amendments.
NIST AI Risk Management FrameworkVOLUNTARY
A structure for risk work — govern, map, measure, manage. Prescribes practice, imposes no obligation.
NIST Generative AI ProfileVOLUNTARY
The same framework narrowed to generative systems, enumerating risks specific to models that produce text and images.
OWASP LLM Top 10PRACTITIONER
Failure modes observed in deployed LLM applications: prompt injection, sensitive data disclosure, supply chain, excessive agency.
THE CORPUS04
The constraint that shapes retrieval

Overlapping subject,
different legal force.

Passages from a voluntary framework and a binding regulation are near neighbours in meaning. An answer citing NIST for an obligation the Act imposes is fluent and wrong.

Which is why the citation stays attached to the claim rather than being summarised away: the reader can see which instrument the answer rests on.

THE CORPUS05
Architecture

Built once. Then run
on every question.

Built once, offline
01Parse each document into citable sections Articles, annexes, numbered sections — the unit a reader would cite
02Split into passages Boundaries chosen so a rule is never severed from its conditions
03Embed each passage Local model, CPU. The index is a file that ships with the application
Per question
04Rank every passage by semantic similarity
05Expand: the article's opening, then its cross-references The two deterministic steps that carry the work
06Answer with citations, or abstain
THE PIPELINE06
Where similarity alone fails

Some provisions are split across two sections, and neither is sufficient alone.

Annex IIIlists CV screening as high-risk
→
Article 6states the conditions that apply

Retrieving more passages does not surface the second. It is not semantically near the question — it is referenced by the first.

MULTI-HOP07
The mechanism that resolves it

Cross-references are
extracted at parse time
and followed at query time.

When a retrieved passage cites another section, that section is pulled into context with it.

Deterministic: no agent, no planner, no second model call, and no capacity to invent a link that is absent from the text.

THE MECHANISM08
Abstention

Similarity search always
returns its nearest
passages.

However far away they are. There is no native signal for “this corpus does not contain the answer.”

Measured here, retrieval confidence could not separate answerable questions from unanswerable ones. Abstention is therefore enforced at generation, against the retrieved text, rather than by thresholding a score.

ABSTENTION09
Building it is the tractable half

Any RAG system will
produce a fluent answer
to any question.

Fluency is not evidence that retrieval succeeded. A demonstration answer establishes nothing about the system that produced it.

The questions that matter: did it retrieve the sections the answer requires, did it ground each claim in them, and did it abstain when it could not.

EVALUATION10
The flaw in the first evaluation
HELD-OUT SET · BLIND GRADING

Retrieval parameters were
selected against the same
set used to report results.

Every figure was in-sample. So: a second set, written from sections the first never touched, keys committed before execution, and both sets graded by a separate model blind to the pipeline.

Scores fell. The independent grader also surfaced a defect in my own refusal detection that self-review had not.

HELD OUT11
What I'd take from it

RAG isn't “put
documents in a model
and ask questions.”

It's the source data. The retrieval logic. The failure modes.

And whether the evaluation is testing the system, or confirming the choices already made.

Method, figures, and the failures that remain — including one question it has never retrieved — are in the repository.
